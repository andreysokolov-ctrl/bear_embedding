# Разбор предоставленных скриншотов DeepSeek

Скриншоты прочитаны как рекомендации, а не как спецификация API. Ниже указано,
какие решения приняты в коде и где обобщения требуют исправления.

| Рекомендация | Оценка и принятое решение |
|---|---|
| Линейная схема ingestion -> query building -> embedding | Для BEAR это две ветви: документы и вопросы. Вопрос не строится из каждого документа. Соответствует страницам 20-21 презентации. |
| Одна модель для документов и вопросов | Принято. Проверяется профиль провайдера/токенизатора и сохраняется embedding_profile_id. Размерность сама по себе совместимость не доказывает. |
| Одинаковая препроцессинг-логика и префиксы | Уточнено: правила должны соответствовать модели. E5 требует `query:` для вопросов и `passage:` для документов; BGE-M3 не требует query instruction. Асимметрия сама по себе не ошибка. |
| Универсальный BGE-префикс Represent this sentence… | Не перенесён на BGE-M3. Карточка BGE-M3 явно говорит об отсутствии обязательной инструкции. |
| NFC, пробелы, осторожность с lowercase/stemming | Принято для запроса. Не удаляем регистр, отрицания, слова «найди» и технические обозначения. Документный embedding_text не изменяем, чтобы сохранить код, таблицы и связь с источником. |
| Добавлять заголовки/section в чанк | В upstream уже реализован ChunkContextBuilder. Используем готовый embedding_text без повторного обогащения. |
| Chunk ID, doc ID, source, section, порядок | Сохраняем существующие Chunk/ProcessingResult, а не создаём конфликтующую схему. Tenant/space/version/generation добавляет прежний Qdrant-адаптер. |
| Overlap обязателен, диапазон 200-600 оптимален | Это гипотезы для эксперимента, не универсальные требования. Структурные строки таблиц и parent-child могут требовать иных правил. Новая часть не меняет чанкинг без измерения качества. |
| 512 токенов как предел каждого запроса | Число зависит от профиля. Считаем токены с префиксом и special tokens, превышение отклоняем. У BGE-M3 физический максимум 8192; рабочий профиль ограничен сильнее. |
| Один язык корпуса и запроса | Не обязательное условие для мультиязычных моделей. Автоматический перевод не включён; его нужно сравнивать отдельно и сохранять исходный запрос. |
| Нормировать векторы | Принято: явная L2-нормализация, проверка размерности/NaN/Inf/zero. Qdrant Cosine тоже нормализует; явная норма упрощает ручной dot-product и тестирование. |
| Кэш sha256(text) | Недостаточный ключ. Добавлены профиль с ревизиями, назначение, рабочий лимит, версия реализации и подготовленный текст. Кэш ограниченный, opt-in, в памяти; Redis можно подключить по VectorCache. |
| Батч 32-64 на 16GB, fp16 вдвое быстрее | Не гарантия. Память и скорость зависят от длины/батча/сервера. По умолчанию 16; dtype и загрузка весов принадлежат Infinity. Новые цифры VRAM/скорости не выдумываются. |
| Держать модель загруженной | Реализуется внешним Infinity. Класс переиспользует HTTP-клиент и провайдер, а не загружает модель на запрос. |
| Асинхронность и vLLM | Есть aembed через asyncio.to_thread для sync-контракта. Для high-load нужен самостоятельный async-провайдер/пул; текущий класс сериализует вызовы. Infinity остаётся согласованным сервером проекта. |
| HyDE / rewriting / expansion / multi-query / история | По умолчанию выключены. Один query_transform разрешён с обязательной builder_version. Полная история не склеивается. Multi-query требует отдельного слияния результатов (например RRF), его нельзя заменить средним вектором без проверки. |
| Логировать исходный и обработанный вопрос | PreparedQuery возвращает оба значения. Вывод содержимого в общий лог opt-in; метрики стадий обходятся без текста. |
| Для чанкинга nDCG, для query building MRR | Все три качественные метрики полезны в каждом эксперименте. Фиксируем остальные слои, а не выбираем одну метрику исключительно по названию слоя. |

## Как валидировать изменения

1. Заморозить корпус, qrels, модель/ревизию, поиск и реранкер; менять только сборку запроса.
2. Сохранить original, normalized, final text, builder_version, профиль и ранжированные ID.
3. Посчитать nDCG@10, MRR@10, Recall@50; отдельно измерить время всего запроса.
4. Для смены чанкинга сначала перенести qrels на новые ID или оценивать стабильные document-ID.
5. Не объявлять рост на 200 вопросах статистически значимым без соответствующей проверки.

Общие исправления подтверждены первичными источниками (проверены 05.11.2026):

- [BAAI/bge-m3, модельная карточка: FAQ и Specs](https://huggingface.co/BAAI/bge-m3)
- [intfloat/multilingual-e5-small, модельная карточка](https://huggingface.co/intfloat/multilingual-e5-small)
- [Infinity, официальный клиент/API](https://github.com/michaelfeil/infinity/blob/main/docs/docs/client_infinity.md)
- [Qdrant, коллекции и Cosine](https://qdrant.tech/documentation/manage-data/collections/)

Сравнение моделей из скриншотов не заменяет наш RuBQ-бенчмарк. Новых выводов о лидерстве
Qwen 4B/8B или требуемой VRAM из этих рекомендаций не делаем.
