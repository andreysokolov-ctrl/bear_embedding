# BEAR: парсинг документов и чанкинг

Экспериментальная сборка для подготовки корпоративных документов к поиску в RAG: извлекает текст и таблицы, делит содержимое на чанки, проверяет покрытие и позволяет посмотреть этапы в локальном демо.

## Библиотеки и компоненты

| Библиотека / компонент | Назначение |
|---|---|
| **Chonkie 1.7.0** | Семантическое и рекурсивное разбиение текста в составе адаптивного маршрутизатора. |
| **Razdel** | Выделение предложений с сохранением исходных подстрок. |
| **markdown-it-py** | Разбор Markdown: заголовки, списки, код и таблицы. |
| **BeautifulSoup + lxml** | Обход HTML и извлечение элементов и таблиц. |
| **Dedoc 2.8** | Разбор DOCX через отдельный процесс и адаптер к общей модели; требуется внешний репозиторий участника. |
| **pdfplumber** | Извлечение текста, геометрии и части таблиц PDF. |
| **pypdfium2 + Pillow** | Рендеринг страниц PDF для OCR и работа с изображениями. |
| **Tesseract OCR** | Внешняя программа для распознавания текста сканов и отдельных областей PDF. |
| **transformers + sentencepiece** | Локальный токенизатор E5 и контроль длины входа модели. |
| **httpx** | HTTP-клиент сервиса embeddings и Qdrant в базовом пакете. |
| **NumPy** | Работа с числовыми массивами при обработке векторов. |
| **FastAPI + Pydantic + Uvicorn** | Тестовый HTTP API базового пакета; интерфейс Fusion-демо использует стандартный HTTP-сервер Python. |
| **psutil** | Контроль ресурсов процессов локального демо. |
| **pytest** | Проверки парсинга, чанкинга и интеграционных контрактов. |
| **Infinity / совместимый embedding endpoint** | Внешний инференс для семантического разбиения и векторов; в офлайн-демо используется резервный путь. |
| **Qdrant** | Векторное хранилище, для которого есть адаптер в базовом пакете; в Fusion-демо индексация отключена. |

Используются два пакета: `bear-text-beta/` — модели данных, маршрутизация, проверка чанков, embedding- и Qdrant-адаптеры; `bear-fusion-lab/` — сборка парсеров, обработка таблиц, PDF/OCR и локальное демо. PDF через Docling проверялся отдельно, но в демо он не подключён.

## Архитектура и данные

Вход: файл TXT, Markdown, HTML, DOCX или PDF и `DocumentContext` с `tenant_id: str`, `space_id: str`, `document_id: str`, `document_version: int`, `filename: str`, `mime_type: str`, `checksum: str`. Локальное демо создаёт контекст задания самостоятельно.

```text
Файл + DocumentContext
  → проверка файла, лимитов и сохранение оригинала
  → парсер по формату → ParsedDocument (упорядоченные ContentBlock)
  → нормализация и подготовка таблиц
  → adaptive: whole / structural / semantic / recursive
  → проверка размеров, покрытия и источников; safe repair при необходимости
  → Parent–Child и breadcrumb → ProcessingResult → JSON
  → локальный поиск BM25 и просмотр этапов в демо
```

TXT разбирается встроенным парсером, Markdown — `markdown-it-py`, HTML — BeautifulSoup, DOCX — Dedoc через внешний процесс, PDF — `pdfplumber` с OCR через Tesseract по необходимости. `ParsedDocument` содержит `context`, `blocks`, `attachments`, `warnings` и профиль парсера. Каждый `ContentBlock` имеет тип `TEXT`, `TABLE` или `IMAGE`, роль, текст, порядок, путь раздела, `SourceLocator` и метаданные. Источник может содержать строки, путь элемента, страницу и координаты; точность зависит от парсера.

Таблицы переводятся в канонические ячейки с координатами и объединениями. Ячейки одной строки объединяются, если помещаются в токенный бюджет; длинные значения делятся на части. Валидатор проверяет покрытие значений и привязку к заголовкам.

Адаптивный маршрутизатор сохраняет небольшой участок целиком, использует структурное разбиение для явно структурированного содержимого, семантическое — для подходящего связного текста, рекурсивное — как основной альтернативный и резервный путь. При недоступном инференсе семантическое разбиение переходит на резерв. Финальная проверка контролирует вход модели с учётом контекста; стандартный профиль: цель 320, максимум 480 токенов.

Выход `FusionPipeline.process_path(...)` — JSON-совместимый словарь с `schema_version`, `original`, `parser_runtime`, `result`, `quality`, `parents` и `accepted_for_indexing`. В `result` находятся `context`, `processing_profile_id`, `generation_id`, `parsed_document`, `chunks`, `deferred_blocks`, `warnings`, `completeness` и `metrics`.

Пример одного элемента `chunks` (сокращённый):

```json
{
  "id": "uuid", "sequence": 0,
  "text": "Текст фрагмента", "embedding_text": "Раздел\nТекст фрагмента",
  "token_count": 15, "section_path": ["Раздел"],
  "source_spans": [{"block_id": "block-id", "start_char": 0, "end_char": 16}],
  "attachment_ids": [], "strategy": "structural", "fallback_reason": null,
  "metadata": {"parent_id": "uuid", "parent_ids": ["uuid"], "chunk_order": 0, "breadcrumb": "Раздел"}
}
```

Это пример формы: фактические текст, идентификаторы, границы, стратегия и размер зависят от документа и профиля. `source_spans` — полуоткрытые диапазоны символов внутри нормализованного блока. `partial` и предупреждения указывают на неполную обработку; прохождение проверки чанков не гарантирует правильность OCR или исходного парсинга.

## Запуск и зависимости окружения

Fusion рассчитан на Python 3.12. Помимо Python-пакетов нужны локальный токенизатор `intfloat/multilingual-e5-small`, Tesseract с `eng` и `rus` для OCR и отдельное окружение Python с Dedoc для DOCX. Модели, виртуальные окружения, документы и результаты пользователей в репозиторий не включены.

На Windows из корня репозитория:

```powershell
py -3.12 -m venv bear-text-beta/.venv
./bear-text-beta/.venv/Scripts/python.exe -m pip install -e './bear-text-beta[dev]'
./bear-text-beta/.venv/Scripts/python.exe -m pip install -e './bear-fusion-lab[demo]'
```

Для DOCX требуется чистая копия [RAG_VERSION_1](https://github.com/tema-coder/RAG_VERSION_1) на commit `a48d88d21ba6ece0fc37eb1f91f18905705dec7f` и отдельный Python с установленными зависимостями парсера. Worker проверяет commit и отсутствие изменений отслеживаемых файлов. Подготовьте локальный токенизатор E5; пути к нему, репозиторию и Python указываются явно:

```powershell
./bear-text-beta/.venv/Scripts/python.exe ./bear-fusion-lab/demo.py `
  --upstream 'ПУТЬ_К_RAG_VERSION_1' `
  --parser-python 'ПУТЬ_К_PYTHON_ПАРСЕРА' `
  --tokenizer 'ПУТЬ_К_ТОКЕНИЗАТОРУ_E5'
```

Откройте http://127.0.0.1:8765 и загрузите документ. Без embedding endpoint семантический путь использует fallback. Для совместимого сервиса задайте `BEAR_INFINITY_URL` до запуска. Скрипт `bear-fusion-lab/start-demo.ps1` содержит пути прежнего рабочего окружения; для другого компьютера используйте аргументы выше. Полная установка отдельного окружения парсера и запуск с нуля на другой машине пока не подтверждены.

## Ограничения и проверки

Fusion — бета: `accepted_for_indexing=false`, локальный поиск — BM25, генерация ответов и работающий сквозной Qdrant-пайплайн в демо не реализованы. Качество сложных PDF-таблиц, рисунков и чисел OCR требует проверки. Семантическое разбиение с реальными E5-векторами проверено на небольшой контрольной выборке; это не оценка качества на всех документах.

Исходный отчёт о тестах и сравнении версий — [FINAL_INTEGRATION_REPORT.md](bear-fusion-lab/FINAL_INTEGRATION_REPORT.md). Часть исследовательских скриптов и корпусов из исходного рабочего окружения в эту публикацию не включена; ссылки отчёта на них могут быть недоступны.
